$$\mathrm{MR}(m_j \mid t^h_j, g) = {\color{#f97316} \mathbb{E}}_{{\color{#f97316} t^f_j \sim P(t^f_j \mid t_{1:j})}}\, R^*(t_{1:j} \cup {\color{#f97316} t^f_j} \mid g)$$
  • $\mathrm{MR}$: the Multiturn-aware Reward
  • given the history $t^h_j$ and goal $g$
  • assesses the response $m_j$
  • $\mathbb{E}$: the expected value
  • over future turns $t^f_j = t_{j+1:K}$
  • of $R^*$: a score of the whole conversation for goal $g$

Requirement 1: $R^*$ is not observed, so it must be approximated

Requirement 2: future turns must be simulated, and full rollouts are expensive

Sec. 2, p. 2; Sec. 3.1, Eq. 1, p. 3; Sec. 3.1.2, p. 4

Let's make this precise. This is Equation 1 of the paper. Let's read it piece by piece. Click: MR, the Multiturn-aware Reward. Click: it is computed given the history t h j, meaning all previous turns plus the current user input u j, and the user's implicit goal g. Click: what it assesses is the model's response m j. Click: it is an expected value, Click: over the future turns t f j, the turns that come after the response. We don't have them, so we sample them with a user simulator. Click: and what we take the expectation of is R star, a score of the whole multiturn conversation, history, response and future, against the user's final goal g. The authors frame this as causal effect estimation: the response is an intervention, and MR measures its effect on how the conversation ends. But we can't compute it directly. Click: first requirement: we never observe R star itself, so the paper has to approximate it with rewards it can measure. That's the next slide. Click: second requirement: we don't have the future turns. They must be simulated, and rolling every conversation out to the very end would be too expensive. The slide after that shows how the paper limits this.

Approximation of MR: Conversation-level reward

$$R^*(t \mid g) \simeq R_{\text{ext}}(t, g) + R_{\text{int}}(t)$$
$$R^*(t \mid g) \simeq {\color{#f97316} R_{\text{ext}}(t, g)} + R_{\text{int}}(t)$$
$$R^*(t \mid g) \simeq R_{\text{ext}}(t, g) + {\color{#f97316} R_{\text{int}}(t)}$$
✓

Task success

$R_{\text{ext}} = S(\mathrm{Extract}(t), y_g)$: BLEU, pass rate or accuracy against the reference

⏱︎

Efficiency

$-\min[\lambda\,\mathrm{TokenCount}(t), 1]$: fewer tokens to read and write

⇄

Interactivity

$R_{\text{LLM}}(t) \in [0, 1]$: an LLM judge rates engagement

Sec. 3.1.1, Eq. 2–4, p. 3

First ingredient: the conversation-level reward R star. The paper approximates it as an extrinsic plus an intrinsic reward. Click: the extrinsic reward is task success. Extract pulls the final solution out of the conversation, here the document, the code or the answer, and a task metric S compares it to the reference y g: BLEU for documents, pass rate for code, accuracy for math. Click: the intrinsic reward has two parts. The first is efficiency: a penalty on the number of tokens the user has to read and write, scaled by lambda and capped at 1. Lambda is 1e-4 for documents and 5e-4 for code and math. Click: the second is interactivity: an LLM judge gives a score between 0 and 1 for how engaging the conversation was. So a model can't just ask endless questions: that costs tokens and doesn't solve the task.

Second requirement: sampling the future. Rolling every conversation out to the end is too expensive, so the paper caps the lookahead with a window size w. Here w is 2, the setting used in all main results. We start from the history, in grey, and the current user turn u j. Click: the model proposes a candidate response m j, in orange. Click, click, click, click: a user simulator, an LLM role-playing the user with the hidden goal g, plays the next user turn, the model answers, the user replies again, the model answers again. That's the window of two future turns. Click: we score this rollout with the conversation-level reward and get its MR. In the paper's Figure 8 example it's 3.2. In practice the future is sampled 3 times per response and the rewards are averaged. Click: a second candidate response from the same history goes through the same process and gets 2.7.
